# 検証要件

初期資料 `docs/vm-list.md` に記載された目的と環境上の制約を整理しています（整理日: 2026-09-22）。以下の確認条件は、その目的を検証するための計画であり、成功済みの結果ではありません。現在の結果は [検証状況](validation.md) に記録します。

## 目的と確認条件

| ID | 要件 | 確認条件（計画） |
|---|---|---|
| R-01 | NVIDIA BCM による PXE ブート・OS 展開 | コントロールプレーン 3 台・ワーカー 3 台で BCM を介した PXE ブートから OS 展開・起動まで確認する |
| R-02 | コントロールプレーン 3 台・ワーカー 3 台の Kubernetes クラスタ | 各ノードの役割と Ready 状態を確認し、テスト用ワークロードの起動・基本通信を確認する |
| R-03 | Multus による Pod へのセカンダリネットワーク追加 | 対象 Pod に追加インターフェースと意図したアドレスが設定され、ワーカー間でセカンダリネットワーク経由の Pod 通信を確認する |
| R-04 | TopoLVM によるノードローカルストレージの動的割り当て | 各ワーカーの追加ディスクを LVM / TopoLVM 用に設定し、PVC の動的割り当て、Pod へのマウント、読み書きを確認する |

具体的な導入バージョン、設定値、テスト用マニフェストは構築時に確定し、該当する手順・記録へ追記します。

## 前提・対象範囲

- KVM / QEMU・libvirt 上の VM を使用します。構成は [環境構成](environment.md)、割り当ては [VM 一覧](vm-list.md) を正とします。
- BCM ヘッドノード 1 台と Kubernetes 用ノード 6 台を用意します。
- ワーカーの追加 NIC は Multus、OS と独立した追加ディスクは TopoLVM の検証に使用します。
- GPU は割り当てず、GPU ワークロードや GPU デバイス管理の動作は今回の確認対象に含めません。
- 全 VM を単一の物理ホスト上に配置するため、物理ホスト障害への耐性は確認できません。

コントロールプレーンを 3 台にすることと、フェイルオーバーが実証済みであることは区別します。ノード停止などの障害試験の範囲・判定条件は現時点で未定です。

## 構築前に確認する事項

- **BCM ライセンス**: 製品資料では ISO 同梱の標準評価ライセンスを最大 2 ノードと説明しています。今回のヘッドノード 1 台と管理対象 6 台に適用できるライセンスのノード上限・期限を確認します。実機で確認したライセンスの状態と不足は [検証状況](validation.md) を参照してください。
- **Kubernetes の役割配置**: BCM の構築ウィザードではヘッドノードがコントロールプレーン・etcd に初期選択されるとの説明があります。専用コントロールプレーン 3 台を使う本構成に合わせ、対象ノードを明示的に選択し、etcd の配置も確定します。
- **Multus / TopoLVM の導入方法**: 対象バージョンでの互換性と設定手順を確認します。今回参照したマニュアルから、両製品の対応状況や導入済みであることは判断できません。

上記の資料上の根拠とページ番号は [製品資料](references.md) を参照してください。

2026-09-22 の利用者提供ネットワーク構成に基づき、以下も構築前に確認します。設定値と未確定事項は [環境構成のネットワーク](environment.md#ネットワーク) に集約しています。

- **アドレス設計**: Pod CIDR・Service CIDR・Multus 用アドレス範囲を確定し、外部・内部ネットワークを含めた各範囲の重複を避けます。
- **NIC の識別と PXE**: MAC アドレスとゲスト内 NIC 名を照合し、内部 NIC を PXE とクラスタ通信に使います。ワーカーの追加 NIC は Multus 用として区別します。
- **ネットワークサービス**: libvirt が DHCP・DNS を提供しない構成に合わせ、BCM の DHCP・PXE、ノードの DNS・ゲートウェイ、BCM 経由の外部通信を設定・確認します。仮想ネットワークと NIC 接続の作成完了だけでは、これらの動作完了とは扱いません。

## 記録する結果

各要件の検証時には、実施日、対象ノード、使用バージョン、設定・実行内容、期待結果、実際の結果、参照した `input/` 内の証跡を記録します。設定を入力しただけの状態や、関連する前提条件だけを確認した状態を、その要件全体の完了とは扱いません。
