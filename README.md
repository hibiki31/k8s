# NVIDIA BCM / Kubernetes 仮想検証環境

NVIDIA Base Command Manager（BCM）を用い、仮想環境で Kubernetes クラスタの構築・運用を検証するリポジトリです。BCM による PXE ブートと OS 展開、コントロールプレーン 3 台・ワーカー 3 台の Kubernetes 構成、Multus による追加ネットワーク、TopoLVM によるローカルストレージの動的割り当てを検証します。

KVM / QEMU と libvirt を使用し、BCM ヘッドノードを含む 7 台の VM を単一の物理ホスト上に配置します。GPU は割り当てません。物理ホスト障害に対する冗長性は検証対象に含みません。

## リポジトリ構成

```text
.
├── README.md          # プロジェクト概要とドキュメント索引
├── AGENTS.md          # このリポジトリで作業するエージェント向けの方針
├── docs/              # 整理した環境情報・要件・手順・検証記録（Git 管理）
└── input/             # 製品ドキュメント・構築ログ・画面などの一次資料（Git 管理外）
```

## 資料の追加と更新

1. 製品ドキュメントや構築時のログ・画面を、作業単位の `input/<分類>/` に保存します。
2. 資料を確認し、環境に必要な設定・手順・結果を `docs/` の該当文書へ整理します。**実際に実行した手順は、調査・障害対応・リポジトリの保守作業も含め、必ず手順書として保存します。** 作業完了の報告・コミットまでに実行順・前提・結果・証跡・残課題を反映し、失敗や中断も記録します。詳細は [手順書化のルール](AGENTS.md#実行した手順の手順書化必須) に従います。
3. 参照元のパス、製品バージョン、章・ページまたはログの日時を記録し、計画と実際の確認結果を区別します。
4. 進捗が変わったら [検証状況](docs/validation.md) を、新しい文書を追加したらこの索引を更新します。

`input/` 全体は `.gitignore` で除外しています。リポジトリを clone しても一次資料は含まれません。`docs/` は資料が手元になくても構成や確認結果を読めるように記述し、原本が必要な場合は記載された参照元を使用します。

エージェントによる更新時の詳細は [AGENTS.md](AGENTS.md) を参照してください。
